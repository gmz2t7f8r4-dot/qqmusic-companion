# 在 Aru 里接上这 5 个工具

## 1. 填什么

在 Aru 的 MCP 设置里新增一个服务器，**传输类型选 HTTP（Streamable HTTP）**：

```
https://你的网址/mcp?token=你的MCP_TOKEN
```

如果 Aru 那边只支持 SSE 类型，就改成：

```
https://你的网址/sse?token=你的MCP_TOKEN
```

`你的MCP_TOKEN` 就是 Coolify 环境变量里 `MCP_TOKEN` 的值；真实口令只放在本地 `cloud\.env.local`，不要发到公开地方。

两种通道都开着，填哪个都行；HTTP 那个更省事。

> 也可以不把口令放网址里，改在请求头里填 `Authorization: Bearer <MCP_TOKEN>`。
> 放网址里更方便，但会被服务器访问日志记下来，介意的话用请求头。

## 2. 接上后会有 5 个工具

| 工具 | 干什么 | 可以这样问 |
|---|---|---|
| `get_now_playing` | 当前/最后的播放状态、进度、更新时间 | "我现在在听什么？" |
| `get_lyrics` | 当前歌或指定歌的歌词（可带时间轴） | "这首歌歌词发我" |
| `get_play_history` | 最近七天的播放记录 | "我昨天听了哪些歌？" |
| `get_listening_stats` | 播放次数排行、单曲次数、按天统计 | "这周听得最多的是哪首？" |
| `get_service_status` | 采集器和数据库是否正常 | "听歌记录怎么没更新？" |

## 3. 怎么确认真的能用

依次问 AI 这三句：

1. "我现在在听什么？" → 应该报出歌名、歌手、播放/暂停状态，并带"最后更新时间"。
2. "这周我听歌最多的是哪几首？" → 应该给出排行。
3. "帮我看看听歌采集正常吗？" → `get_service_status` 里 `collector.online` 应为 `true`。

## 4. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 返回 401 | 口令不对或丢了 `?token=` | 检查网址里 token 是否完整 |
| 查不到当前歌，但历史有 | 电脑关机/睡眠/采集器没开 | 看 `get_service_status` 里的最后上传时间 |
| `realtime: false` | 数据超过 60 秒没更新 | 采集器可能停了，双击启动 |
| 歌词 `not_found` | lrclib 没收录 | 正常现象，不会编造 |
| 播放次数比自己感觉的少 | 只统计整首听完（95%）的歌 | 听一半切走的不算 |
| 进度和实际差一两秒 | 进度是按累计播放时间估算的 | 正常，`position_estimated: true` |

## 5. 安全提醒

这个网址等于你听歌记录的钥匙，别发到群里或公开地方。要换就同时改云端的 `MCP_TOKEN` 和 Aru 里的网址。
