# 五个 MCP 工具的输入输出

> 传输方式：HTTP（Streamable HTTP，`/mcp`）或 SSE（`/sse`）。
> 鉴权：`Authorization: Bearer <MCP_TOKEN>`，或网址里带 `?token=<MCP_TOKEN>`。
> 返回都是 JSON。歌名/歌手为 `null` 表示确实没有。

---

## 1. `get_now_playing`

输入：无。

输出：

| 字段 | 含义 |
|---|---|
| `realtime` | `false` 表示数据已过期，不能当实时看 |
| `stale_reason` | `null` / `collector_offline`（电脑离线）/ `media_stale` |
| `playback` | `playing` / `paused` / `stopped` / `none` / `unknown_offline` |
| `track` | `{title, artist, album}` 或 `null` |
| `position_seconds` | 已播放秒数，**估算值** |
| `position_estimated` | 固定为 `true`（QQ 音乐不提供真实进度） |
| `duration_seconds` | 歌曲总时长，查不到为 `null` |
| `duration_source` | `lrclib` / `cache` / `not_found` / `error` |
| `last_updated` | 这条状态是什么时候采到的 |
| `seconds_since_update` | 距今多少秒 |
| `collector` | 设备名、是否在线、最后心跳、待上传条数 |
| `note` | 人话解释（离线、没在放、时长未知等） |

## 2. `get_lyrics`

输入：

| 参数 | 必填 | 说明 |
|---|---|---|
| `title` | 否 | 不传就查当前正在播放的歌 |
| `artist` | 否 | 有就用来精确匹配 |
| `album` | 否 | 同名多版本时用来区分 |
| `duration_seconds` | 否 | 强烈建议传，时长是最可靠的区分依据 |
| `timestamps` | 否 | `true` 优先带时间轴的歌词 |

输出：

| 字段 | 含义 |
|---|---|
| `found` | 是否拿到歌词 |
| `status` | `ok` / `not_found` / `ambiguous` / `error` / `no_lyrics` / `no_current_song` |
| `matched` | 匹配到的歌名、歌手、专辑、时长 |
| `synced` | 歌词是否带时间轴 |
| `lyrics` | 歌词正文（LRC 或纯文本），不存服务器 |
| `candidates` | 不确定时列出候选 |
| `match_quality` | `exact` / `duration` / `album` / `artist` |
| `note` | 失败原因的人话说明 |

---

## 3. `get_play_history`

输入：

| 参数 | 必填 | 说明 |
|---|---|---|
| `date` | 否 | `YYYY-MM-DD`；不传返回七天全部 |
| `title` | 否 | 模糊匹配歌名或歌手 |
| `event_id` | 否 | 精确查某一条 |
| `limit` | 否 | 默认 100，最大 500 |

输出：`retention_window`（保留范围）、`query_range`、`count`、`events[]`。
每条事件：`id`、`title`、`artist`、`album`、`started_at`、`ended_at`、`played_seconds`、`duration_seconds`、`end_reason`。

超出七天的日期一律返回空，不会越界查询。

---

## 4. `get_listening_stats`

输入：

| 参数 | 必填 | 说明 |
|---|---|---|
| `kind` | 否 | `top`（排行，默认）/ `song`（单曲次数）/ `daily`（按天） |
| `title` | `kind=song` 时必填 | 歌名模糊匹配 |
| `limit` | 否 | 排行条数，默认 10 |
| `date` | 否 | 只统计某一天 |

输出：`scope`、`plays`、`played_seconds`、`songs[]` 或 `days[]`。

> 只统计"完整听完"的记录，听一半切歌的不算。

---

## 5. `get_service_status`

输入：无。

输出：

| 字段 | 含义 |
|---|---|
| `ok` | 服务本身是否正常 |
| `database` | 数据库是否可用、总记录数、最后写入时间 |
| `retention` | 七天保留窗口的起止 |
| `collector.online` | 采集器是否在线（60 秒内有无心跳） |
| `collector.last_heartbeat_at` | 最后一次上传时间 |
| `collector.queue_pending` | 电脑上还没传上去的条数 |
| `collector.unknown_duration_skipped` | 因查不到时长而没记的歌曲数 |
| `collector.last_upload_error` | 最近一次上传失败原因 |

不会返回口令或系统信息。
