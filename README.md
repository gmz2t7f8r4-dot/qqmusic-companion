# QQ 音乐听歌伴侣（本地采集 + 云端查询）

一句话：电脑上的采集器在后台盯着 QQ 音乐，**整首听完**才记一条，传到云端；手机上的 Aru 通过 MCP 随时问云端"我刚在听什么、这周听了几遍"。

不需要开着 Aru，也不需要和 AI 对话，采集器自己会记。

> **代码作者**：本项目的代码由 DeepSeek Harness 中的 DeepSeek 模型（deepseek-flash）编写。
> 需求提出、验收和部署由项目所有者完成。

## 一、文件夹里各是什么

```
qqmusic-companion\
├─ 启动听歌采集.bat      ← 日常双击这个（后台运行，不弹窗）
├─ 停止听歌采集.bat      ← 要停就双击这个
├─ 自检（出问题先点这个）.bat  ← 怀疑没记上，先点它看结果
│
├─ local\                ← 【本地采集器】跑在你这台电脑上
│   ├─ collector.py      主程序
│   ├─ config.ini        ← 你唯一需要改的文件（填云端地址）
│   ├─ vendor\           读取 Windows 播放信息用的库（已装好，别删）
│   └─ ...
│
├─ cloud\                ← 【云端服务】部署到服务器（Coolify）
│   ├─ app\              上传接口 + 5 个 MCP 工具
│   ├─ Dockerfile
│   ├─ docker-compose.yml
│   └─ .env.example      要填的口令（已生成好）
│
├─ local-data\           ← 你的数据，和代码分开放
│   ├─ queue.db          还没传上去的记录（传成功就删）
│   ├─ logs\             运行日志，每天一个，自动只留 7 天
│   └─ collector.pid     正在运行的进程号（停止脚本用）
│
├─ tools\                ← 排查/安装脚本（读播放信息、重装依赖）
├─ tests\                ← 逻辑测试（不需要 QQ 音乐也能跑）
├─ docs\                 ← 部署步骤、接口说明
├─ LICENSE               ← MIT 许可证
└─ CREDITS.md            ← 参考过的项目、用到的开源库
```

## 二、第一次使用（只做一次）

1. 云端部署好之后，会得到一个网址，例如 `https://xxxx.sslip.io`。
2. 用记事本打开 `local\config.ini`，在 `base_url =` 后面填这个网址（**不要带 `/mcp`**）。
3. 确认 `collector_token` 和云端环境变量 `COLLECTOR_TOKEN` 是同一串（真实口令在 `cloud\.env.local`）。
4. 保存。

> 从 GitHub 重新下载代码时，`config.ini` 不会跟着来（含口令，故意不提交）。
> 复制一份 `local\config.example.ini` 改名成 `config.ini`，再填上面两项即可。

### 万一本地代码丢了，怎么从仓库恢复

1. 下载仓库（GitHub 上 Code → Download ZIP，或 `git clone`）。
2. 装本地依赖：在项目目录运行 `python tools\fetch_wheels.py`（会下载读取播放信息用的库到 `local\vendor`）。
3. 复制 `local\config.example.ini` → `local\config.ini`，填云端地址和采集口令。
4. 双击 **启动听歌采集.bat**。

云端那边不用重装，在管理面板里点一次重新部署就能拉起来（数据在 `/data` 卷里）。

## 三、日常使用

- 双击 **启动听歌采集.bat**。没有窗口，只在后台跑。
- 正常听歌就行。整首听完的歌会自动上传；听一半切走的不算、不传。
- 要用的时候，在 Aru 里问 AI，例如"我现在在听什么"、"这周一共听了几首歌"。
- 想停：双击 **停止听歌采集.bat**。

电脑重启后不会自己启动（按你的要求），需要再双击一次。

## 四、数据在哪、会不会外泄

- 本地：`local-data\queue.db`（没传出去的记录）和 `logs\`。
- 云端：`/data/qqmusic.db`（七天记录），超出七天自动删。
- 上传走 https，带口令；MCP 查询也要口令。没有别的遥测。
- 不保存音频，也不保存歌词正文。

## 五、出问题了怎么办

先双击 **自检（出问题先点这个）.bat**，它会把"能不能读到 QQ 音乐、能不能连上云端"打印出来。

| 现象 | 先看这里 |
|---|---|
| 双击启动没反应 | `local-data\logs\collector.log` 最后几行 |
| 云端查不到当前状态 | 电脑是否开机、采集器是否在跑、自检里云端连通性 |
| 一直显示"数据可能过期" | 采集器没在跑，或者电脑睡眠了 |
| 某些歌一直不记录 | 这些歌查不到时长（会在"服务状态"里显示漏了几首） |

日志可以直接用记事本打开。

## 六、已经知道的限制（不是 bug）

1. **进度是算出来的**：QQ 音乐不把播放进度交给 Windows（实测恒为 0），所以进度 = 累计播放时间，误差 1~2 秒，返回值里 `position_estimated: true`。
2. **整首听完才记**：按你定的 95% 判定；暂停后不继续的不算。
3. **查不到时长的歌不记**：比如冷门曲、现场版；会在服务状态里累计"因时长未知漏记"数量。
4. **服务重启时正在放的那首**可能不计入（从 0 开始计时）。
5. 只支持 Windows 桌面版 QQ 音乐；手机端、iOS 不采集。
6. 电脑关机期间没有新数据，云端只能查已上传的历史（会明确标注最后更新时间）。

## 八、开发与测试

不需要 QQ 音乐在播，用模拟时间线验证记录逻辑：

```
python tests/test_tracker.py
```

覆盖：完整听完会记、听一半不记、暂停不计时、查不到时长不记、休眠中断不误记。

排查"读不到播放状态"时可以单独看 Windows 给了什么：

```
python tools/probe_session.py
```
